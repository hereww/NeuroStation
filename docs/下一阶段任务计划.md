# NeuroStation 下一阶段任务计划

更新时间：2026-09-13
基线版本：MVP1.0.1 / semantic version 1.0.1
计划目标：从“可演示 MVP”推进到“可控的科研技术验证版本”，并为后续正式实验候选版建立证据链。

## 任务分派规则

- 复杂任务：使用软件中的 `gpt-6`。
- 简单任务：使用软件中的 `gpt5.6luna`，重点处理文案、版本同步、测试补充和机械性重构。
- 所有涉及真实设备、数据隐私、协议放行和发布的任务，由主代理统一复核，不直接接受子代理最终结论。

## P0：先建立正式实验安全门槛

### NS-001 草稿协议与正式协议隔离（已完成第一版）

目标：阻止草稿协议、未审核通道表被误用于正式 Cyton 采集。

范围：`configs/protocols`、通道配置、`CaptureConfig`、SSVEP 页面、结果页、session metadata。

交付：

- 正式协议状态字段与版本号；
- 正式模式禁止 draft protocol；
- 技术验证模式显式显示 `TECHNICAL VALIDATION`；
- session 保存协议版本、通道配置版本和 hash；
- 绕过 draft 的操作记录到 session 和日志。

验收：

- draft 配置启动 Cyton 被阻断；
- Synthetic/Preview 采集入口已移除；生产入口只允许真实 Cyton，历史记录仅可只读查看；
- 结果页、session.json、manifest.csv 都显示模式和版本；
- 负向测试覆盖绕过逻辑。

依赖：无。
建议模型：复杂高推理模型。

### NS-002 采集前硬件 preflight（已完成第一版）

目标：在正式采集前验证串口、Cyton handshake、短时采样和通道基本质量。

交付：

- Preflight 状态机；
- 串口占用、设备不可达、采样平线、掉帧的可操作错误；
- 通过/阻断规则：握手、无样本和非有限数据硬阻断；时间戳抖动、包序列和通道质量作为可追踪 warning，按 OpenBCI GUI 逻辑继续采集；
- 诊断结果写入 session metadata；
- 无硬件环境下的 mock preflight。

验收：

- 无串口、占用串口、握手失败、采样为空均有明确状态；
- 预检失败时不能进入正式采集；
- 无硬件测试只验证 Cyton 预检的拒绝、警告和路由边界，不生成 EEG 数据；
- 真实 Cyton 现场验收清单补齐。

依赖：NS-001。
建议模型：复杂高推理模型。

### NS-003 刺激时序与显示器校准记录（元数据第一版已完成）

目标：把刷新率、屏幕、photodiode/TTL 校准从说明文字变成可追踪记录。

交付：

- 屏幕刷新率检测和记录；
- screen index、分辨率、DPI、显示器名称写入 session；
- photodiode/TTL 校准结果录入入口；
- 刺激时序质量状态。

验收：

- 双屏和不同刷新率下记录正确；
- 刷新率不符合协议时阻断正式模式；
- 结果页能区分“软件帧日志”和“物理时序已校准”。

依赖：NS-001、NS-002。
建议模型：复杂高推理模型。

## P1：数据安全与故障可观测性

### NS-004 用户隐私字段最小化与保护（已完成第一版）

目标：降低本地用户信息和医疗字段的暴露风险。

交付：

- 将医疗字段改为最小化风险筛查状态；
- 导出默认脱敏；
- 用户索引加密或使用 Windows DPAPI；
- 删除、恢复、永久删除策略文档；
- 隐私说明。

验收：

- 原始数据包不包含不必要的姓名/医疗信息；
- 恢复和永久删除行为有测试；
- 导出包不暴露绝对路径和敏感字段。

依赖：NS-001 的 metadata 版本设计。
建议模型：复杂高推理模型。

### NS-005 采集 worker 诊断包（已完成第一版）

目标：让设备失败可以被现场人员定位。

交付：

- 将 worker.log、status.json、quality.json 复制到 session 目录；
- 错误结果页显示诊断摘要；
- “打开目录”“复制路径”“导出诊断包”；
- stdout 不再静默丢失关键诊断信息。

验收：

- worker 启动失败、串口失败、中止、质量异常均生成诊断文件；
- 结果页能打开对应 session；
- 诊断包不包含密钥或不必要的敏感内容。

依赖：NS-001、session file schema。
建议模型：中等复杂度模型。

### NS-006 导入内容 hash 与数据完整性（已完成第一版）

目标：确认 OpenBCI 导入源文件是否被修改。

交付：

- 文件 SHA-256 或分块 hash；
- manifest 保存原始 hash；
- 重复导入状态区分内容相同和内容变化；
- 导入失败保留详细原因。

验收：

- 相同文件重复导入为 skipped；
- 内容变更会重新导入并标记 changed；
- 大文件导入不会造成明显 UI 卡顿。

依赖：NS-005 的诊断和 manifest 约定。
建议模型：轻量模型可先实现，主代理复核。

### NS-007 版本与验收文档统一（已完成第一版）

目标：消除 MVP1.0 与 MVP1.0.1 的文档漂移。

交付：

- 更新 `docs/项目验收报告.md`；
- README、release note、报告统一版本和日期；
- 增加 commit、协议版本、通道配置 hash 字段；
- 生成脚本或检查器。

验收：

- CI 检查文档版本与 `neurostation_contract.py` 一致；
- 发布包内版本信息一致；
- 诊断输出与报告字段一致。

依赖：NS-001。
建议模型：轻量模型。

## P1：UI 工作流改造

### NS-008 采集前向导（分段提示第一版已完成）

目标：把 SSVEP 页面从参数表改成“参与者 → 协议 → 设备检查 → 开始”的流程。

交付：

- 新建采集向导；
- 高级参数折叠；
- 固定显示当前模式、用户、协议、保存位置；
- 风险和 draft 状态使用阻断式提示。

验收：

- 新用户完成必要登记、风险确认和 Cyton 预检后才能进入真实采集；
- Cyton 不能跳过 preflight；
- 状态在窗口窄尺寸和高 DPI 下可读。

依赖：NS-001、NS-002、NS-003。
建议模型：复杂高推理模型。

### NS-009 实时采集页

目标：突出当前试次、倒计时、设备质量和停止操作。

交付：

- Trial x/y；
- 当前频率和目标；
- 采样质量指示；
- 固定停止按钮和 Esc/Q 快捷键；
- 中止后的安全保存状态。

验收：

- 采集过程中 1 秒内看到状态变化；
- 任何错误都不会让停止按钮消失；
- 中止后结果页明确显示部分数据。

依赖：NS-005。
建议模型：复杂高推理模型。

### NS-010 结果页质量摘要（已完成第一版）

目标：结果页先回答“数据是否可用”，再展示文件路径。

交付：

- Completed / Aborted / Error 标签；
- 样本数、时长、通道数、掉帧、事件数；
- 质量通过/警告/失败状态；
- 打开目录、复制路径、导出诊断。

验收：

- Cyton 与 Imported 两种生产来源文案不混淆；
- 历史模拟数据明确标识为只读旧记录，不得作为新实验数据；
- 质量报告和结果页数值一致。

依赖：NS-005、NS-006。
建议模型：中等复杂度模型。

### NS-011 数据集页面改为实验记录管理（筛选第一版已完成）

目标：提升多用户、多会话后的检索效率。

交付：

- 状态、来源、用户、质量、日期、样本数列；
- 只看异常、未关联、导入数据筛选；
- 页面实例持久化，保留筛选、排序、滚动位置；
- 大数据集列表分页或懒加载。

验收：

- 页面刷新后搜索词和排序保持；
- 1000 条会话记录下页面仍可操作；
- 导入期间不阻塞主 UI。

依赖：NS-006、NS-010。
建议模型：复杂高推理模型。

3. NS-002 硬件 preflight。

5. NS-004 隐私字段最小化与保护。

10. NS-006 导入 hash。
11. NS-011 数据集管理。
12. NS-012、NS-013 发布质量。

## 每个任务的统一完成定义

- 有实现或明确的文档变更；
- 有正向和负向测试；
- 不破坏现有 41 个核心/集成测试与 26 个 UI 测试；
- 至少完成一次真实 Cyton 端到端采集；无硬件 CI 不伪造该验收；
- session metadata、manifest 和结果页字段一致；
- 更新 README、验收报告或 release note 中受影响的边界；
- 在真实 Cyton、显示器和隐私策略尚未验证时，不宣称为正式实验候选版。

## 当前边界

- 真实 Cyton、photodiode/TTL、多显示器实机和安装器签名需要现场或发布环境验证；
- 这些边界不影响当前 UI、打包和诊断回归结果；真实采集必须在连接 Cyton 的现场环境完成。

# 离线分析与目标标记审计

审计日期：2026-09-14（北京时间）  
适用版本：NeuroStation 1.0 工作区当前代码
范围：SSVEP 采集、目标标记、倒计时/采集同步、原始列定义、离线分析与证据边界

当前 SSVEP 采集按单眼会话执行。每个会话必须带有 `eye_side`（`left` 或
`right`），并在 `session.json` 的 `display` / `screen_mapping` 中记录主显示器
的左右半区几何。选中眼别对应半区呈现四目标刺激，另一半始终为黑色；
单屏环境可以启动可视采集。`events.tsv` 与 `frame_timing.tsv` 同步记录眼别、基础
数据集名、生成后的数据集名、实际屏幕编号/名称/几何信息。该信息只说明软件呈现
配置，不替代眼罩、受试者视野校准或眼动真值。

## 一、审计结论

| 项目 | 审计结论 | 证据状态 |
| --- | --- | --- |
| 实际呈现的目标 | 已记录为 `presented_target_id` | 软件事实 |
| 实际注视的目标 | 可用全屏窗口的 `1–4` 键作人工/自报标记，写入 `gaze_target_id` | 不是眼动测量 |
| EEG 自动识别目标 | 新增 NumPy FFT 基线，输出 `eeg_predicted_target_id` | 算法推断，需验证 |
| 倒计时与采集同步 | EEG 流在倒计时开始前启动；`acquisition_start` 与 `session_start` 分离记录 | 软件可追溯；物理延迟仍需仪器测量 |
| 原始数据题头 | `raw_brainflow.tsv` 增加题头；`raw_columns.tsv` 给出列意义 | 已实现 |
| 离线分析 | `analyze_ssvep_session.py` 只读会话文件，不连接设备、不改写原始 EEG | 已实现 |

重要边界：程序呈现了某个目标，不等于受试者看了该目标；EEG 在某个频率有峰值，也不等于已经证明眼睛注视了该目标。要证明“实际注视”，至少需要眼动仪、校准后的视线数据，或独立的行为/光学验证。当前的键盘标记只能作为人工/自报标签。

## 二、目标标记模型

每个刺激试次现在应区分四种字段：

| 字段 | 含义 | 能否作为真实注视证据 |
| --- | --- | --- |
| `planned_target_id` | 协议计划呈现的目标 | 否 |
| `presented_target_id` | 软件实际进入刺激流程并呈现的目标 | 只能证明软件流程 |
| `gaze_target_id` | 受试者按 `1–4` 或操作员输入的目标标记 | 否；属于人工/自报 |
| `eeg_predicted_target_id` | 离线 EEG 算法得分最高的目标 | 否；属于模型推断 |

### 2.1 人工/自报目标标记

正式全屏刺激时，按键含义固定为：

| 按键 | 目标位置 |
| --- | --- |
| `1` | `top_left` |
| `2` | `top_right` |
| `3` | `bottom_left` |
| `4` | `bottom_right` |
| `Esc` / `Q` | 中止采集 |

标记写入 `events.tsv`，其 `source` 为 `manual_gaze_annotation`，`label_source` 为 `keyboard_self_report_or_operator`。这类标记必须在报告中称为“人工/自报目标”，不能称为“眼动真值”。

### 2.2 正式实验推荐的真值方案

若问题是“受试者到底看了哪个目标”，建议增加独立眼动流：

1. 眼动仪与 EEG 使用同一实验会话 ID；
2. 眼动仪先做 9 点或项目规定的屏幕校准；
3. 将每个目标的屏幕矩形记录到协议副本；
4. 用注视点落在哪个矩形内生成 `gaze_target_id`；
5. 保存眼动原始数据、校准误差、丢样和映射规则；
6. 用人工/自报和眼动结果比较，发现不一致时保留两者，不覆盖任何一方。

如果暂时没有眼动仪，应把“实际注视目标”改写为“呈现目标”或“人工标记目标”，不要在 UI 或数据表中制造确定性。

## 三、倒计时、采集和刺激的时间关系

当前流程的时间层次如下：

```text
acquisition_start  ->  visible_countdown  ->  session_start  ->  stimulus_onset
       EEG 流开始          准备阶段             实验零点             第一个刺激
```

含义：

- `acquisition_start`：BrainFlow `start_stream()` 成功后写入的事件；倒计时数据会被保留；
- `session_start`：倒计时结束、正式实验时间轴开始的 marker；
- `stimulus_onset`：某个目标开始呈现的 marker；
- `stimulus_offset`：该目标结束呈现的 marker；
- `session_end` / `abort`：正常结束或中止。

软件时间无法单独证明屏幕物理亮起的时间。正式放行前必须使用 photodiode、TTL 或其他独立仪器测量：

```text
刺激物理 onset - EEG marker 样本时间
刺激物理 offset - EEG marker 样本时间
帧间隔、掉帧和实际显示器刷新率
```

`events.tsv` 的时间字段含义：

| 字段 | 含义 |
| --- | --- |
| `monotonic_s` | 本机单调时钟，相对工作进程启动 |
| `wall_time_iso` | 带时区的本机日历时间，仅用于追踪和人工对照 |
| `sample_index` | marker 在保存的原始矩阵中的样本序号；匹配到时填写 |
| `sample_time_s` | BrainFlow/设备时间戳；匹配到时填写 |
| `recording_time_s` | 以 `session_start` 的设备时间为 0 的相对时间 |

分析时应优先使用 `sample_index` 和 `sample_time_s`，不应把 Windows 日历时间当作 EEG 样本时间轴。

## 四、原始数据列题头与意义

`raw_brainflow.tsv` 是“每行一个样本、每列一个字段”。列顺序为：

```text
sample_index, eeg_ch1 ... eeg_chN, package_num, accel_x/y/z,
analog_chN, other_chN, timestamp_s, marker
```

实际列以会话内的 `raw_columns.tsv` 为准，因为不同 BrainFlow board 的行数和辅助通道不同。

| 列名模式 | 意义 | 单位/说明 |
| --- | --- | --- |
| `sample_index` | 保存文件内连续样本号 | 从 0 开始，不是设备包号 |
| `eeg_ch1` ... | EEG 原始通道 | 单位由设备/BrainFlow 配置决定；必须结合通道配置解释 |
| `package_num` | BrainFlow 包序号 | 用于检查丢包和包顺序 |
| `timestamp_s` | 设备时间戳 | 秒；用于事件对齐和有效采样率检查 |
| `marker` | 插入的数据 marker | marker code；对应 `events.tsv.marker_code` |
| `accel_x/y/z` | 加速度辅助通道 | 用于动作/伪迹对照，不属于 EEG |
| `analog_chN` / `other_chN` | 板卡辅助行 | 只有配置支持时才有，不能按列号臆测 |
| `board_row_N` | 未被当前 BrainFlow 描述识别的原始行 | 必须回到 `raw_columns.tsv` 和 board 文档确认 |

通道位置仍由 `channel_config.json` 决定。`eeg_ch1` 不自动等于 `O1`、`O2` 或任何头皮位置；只有正式通道配置填写并审核后，才可以把板卡通道映射到电极位置。

## 五、打开会话后的离线分析流程

### 5.1 先做完整性检查

按以下顺序检查：

1. `session.json`：确认 `status`、`board`、采样率、通道数和 `validation_mode`；
2. `manifest.csv`：确认文件哈希和文件是否完整；
3. `quality.json`：查看有效采样比例、时间戳间隔、平线通道和掉帧；
4. `raw_columns.tsv`：确认每个列名对应的 BrainFlow row；
5. `events.tsv`：确认 onset/offset 是否有 `sample_index` 和 `sample_time_s`；
6. `channel_config.json`：确认 EEG 通道位置、参考、BIAS、AGND 和接线；
7. `frame_timing.tsv`：查看计划帧、实际帧、迟到和掉帧。

### 5.2 运行基线分析

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe analyze_ssvep_session.py `
  .\path\to\session_YYYYMMDD_HHMMSS_mmm
```

分析会生成两个派生文件：

| 文件 | 内容 |
| --- | --- |
| `trial_features.tsv` | 每个试次的窗口、目标、FFT 得分、预测结果和一致性字段 |
| `analysis.json` | 分析方法、样本率、试次数、呈现目标准确率、人工标记准确率和限制 |

分析器不会覆盖 `raw_brainflow.tsv`、`events.tsv` 或其他原始文件。旧会话如果没有带题头的 `raw_brainflow.tsv`，应先单独转换并保留原文件，不应静默把第一行数据当成列名。

## 六、SSVEP 理论依据

### 6.1 为什么可以看目标频率

周期性视觉刺激会在视觉系统和 EEG 中产生与刺激频率相关的稳态响应。工程上可以把每个刺激窗口切出来，在频域观察目标频率 `f` 及其二次谐波 `2f` 的能量。当前基线使用：

```text
score(target) = normalized_power(f) + 0.5 * normalized_power(2f)
```

对四个候选频率分别计算 score，最高者作为 `eeg_predicted_target_id`。这是透明的频谱基线，适合先验证数据链路；它不是已经训练完成的通用分类器。

### 6.2 理论依据的可证伪验证

“频率峰值存在”与“目标识别有效”是两件事，必须分层证明：

**A. 时序证明**

- photodiode/TTL 测量刺激物理 onset；
- 比较物理 onset 与 EEG marker 的 `sample_time_s`；
- 报告均值、标准差、最大偏差和掉帧；
- 不满足时序门槛时，不进入算法准确率结论。

**B. 信号存在性证明**

- 对每个试次、每个通道计算目标频率和谐波功率；
- 与邻近频点或置换标签比较，而不是只看一张 FFT 图；
- 报告跨试次的效应量、置信区间和多重比较处理；
- 检查静息段、空屏段和错误标签段作为阴性对照。

**C. 分类证明**

- 以 `presented_target_id` 作为协议标签时，按受试者内交叉验证；
- 不能随机切分同一试次的相邻窗口到训练集和测试集；
- 报告 balanced accuracy、混淆矩阵、每个目标的召回率；
- 与频率峰值基线、随机猜测和标签置换基线比较。

**D. 注视证明**

- 将 EEG 预测与眼动真值比较；
- 单独报告“预测呈现目标”的准确率和“预测真实注视目标”的准确率；
- 如果没有眼动数据，不能把后一项写成已证明。

### 6.3 还需要哪些算法

当前 FFT 基线之后，可以按数据量和验证结果增加：

1. CCA：将 EEG 与目标频率的正弦/余弦参考信号比较；
2. FBCCA：多个频带分别计算 CCA 后加权；
3. TRCA / eTRCA：有足够重复试次时利用任务相关空间结构；
4. 个体化校准模型：按受试者、显示器、通道配置单独训练；
5. 眼动融合：将 EEG、眼动和刺激事件放在同一时间轴后联合判断。

增加算法不能替代时序和标签验证。模型输出应始终保存为派生字段，不能改写原始 marker 或把预测值伪装成实验事实。

## 七、当前放行门槛

在以下条件满足前，项目只能称为“技术验证/科研采集工具”：

- 完成 Cyton 实机稳定采集和通道接线审核；
- 完成实际显示器刷新率、photodiode/TTL 与 marker 偏差测量；
- 完成至少一个有眼动或明确行为真值的数据集；
- 完成跨受试者或预先声明的受试者内交叉验证；
- 记录数据拒绝规则、伪迹处理、滤波参数、窗口参数和随机种子；
- 将分析输出与原始文件通过 manifest 或派生分析清单关联。

当前实现已经把“可呈现、可标记、可预测、可证明”四件事拆开，但没有把缺失的物理仪器证据自动补出来。

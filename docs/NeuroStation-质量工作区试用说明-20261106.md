# NeuroStation 质量工作区试用说明（审计修复版）

日期：2026-11-06。独立分支 `codex/neurostation-quality-upgrade`，**未合并主线**。
程序产品版本仍为 1.04；请用交付日期、源码身份和 ZIP SHA-256 区分构建，不按产品版本号猜测是否更新。
本轮是工程安全与可核验性修复，不是新个人模型或硬件/临床认证。

## 启动

将 ZIP 完整解压到一个新文件夹，不覆盖以前的可用版本，然后双击：

- `Start-QualityWorkspace.cmd`：直接进入“信号与质量”，不自动采集或播放演示。
- `Start-Workstation.cmd`：主工作站。
- `Start-RealtimeCommands.cmd`：独立指令窗口。实验模型仍默认禁用，包不含 Torch 和个人权重。

启动器清除遗留运行环境绑定，界面可见。录制、设置、诊断及演示输出留在
`%LOCALAPPDATA%\NeuroStationQualityUpgrade`，不写入原项目数据集。

## 无设备检查流程

1. 进入“信号与质量”，点击 **运行 30 秒合成演示**。
2. 查看原始/因果显示轨、频谱、8 通道指标和异常原因。页面必须标记“合成演示”，不是实时脑电。
3. 演示结束，点击 **回放所选会话**。新增的 **封存证据核验** 与在线一致、原始哈希、完整封存分别显示。
4. 点击 **生成质量报告**，查看来源、质量更新条目、试次、指令以及各自分母。
5. 点击 **导出报告副本**，选择独立文件夹。应同时得到 `report.json` 和 `report.html`，不得覆盖旧报告。

“在线一致”现在要求数值核对、封存质量日志/处理清单校验和来源复核均通过。
`replay.json` 另存 `numerical_replay_match`、`quality_evidence_verified` 和具体不一致原因。
**旧会话缺少封存证据时，即便数值相同，也不会显示为已核验通过。** 中止但已封存的已知前缀仍可比较；完整采集状态仍为否。

## 本轮行为变化

- 源文件在报告生成期间被增删或改动：拒绝发布，待采集/编辑停止后再生成。
- 生成或导出时失败/取消：不发布只有一部分文件的报告目录。异常杀进程可能留下以点开头、`.tmp` 结尾的私有临时目录，它不是交付报告，不计通过；不要把它当成可用报告。
- 重新生成失败：清除当前旧报告预览及旧导出入口，但不会删除以前的报告文件。
- 非法质量记录、时间未知/倒挂、索引不合法或重叠：不再沿用上一条正常显示；指令门控拒判，SELECT 锁不会被异常记录重新布防。
- 报告 HTML 最多显示 500 条来源哈希/试次；完整条目保存在 JSON，不丢弃统计记录。

## 验收边界

合成演示不能证明真实电极接触、阈值有效、物理刺激同步或个人模型表现。
局部哈希封存证明的是记录内部一致性，不是外部签名；不要在生成报告时同时修改源文件。
没有事件/标签/评分时保持未知；分母为零显示无法计算，不伪造准确率。

必须由现场操作明确启动真实采集和刺激。硬件阈值、双屏/高 DPI、物理刺激时序、真实 30 分钟负载和 2 小时长稳、全新 Windows 主机仍需分别验收。
全量历史研究测试仍受缺失的训练锁/预注册/数据证据阻塞，详见同日审计报告；不能把专项通过称为全部验收通过。
